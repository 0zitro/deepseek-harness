# @zitro/dsh-oot-ui-composer

[English](README.md) | 中文

富文本 composer 接管：一个纯文本可编辑区，其文本就是完整的 Markdown 源码，实时装饰——强调与代码来自增量 @lezer/markdown 解析加悬空起始符处理（单独的 `_` 立即斜体其尾部，`_**` 叠加，代码上下文抑制一切修饰符，因为由文法而非扫描决定什么是代码）、数学折叠为 KaTeX 排版并带字形到源码的偏移映射、围栏代码用客户端共享的 Shiki 单例着色。

架构移植自 katex-patcher 参考 composer，有两处刻意的偏离。参考实现用 `Range.toString()` 读偏移，因此数学引擎的输出必须不携带文本；这里改用"所持文本"树遍历测偏移，跳过带标记的绘制子树，于是 KaTeX 的 HTML 输出携带文本不再有代价——隐藏的源码留在所持文本里（隐藏从不移除），绘制则在其外。参考实现还逐一枚举其引擎的布局置换；本移植只写下唯一要紧的 KaTeX 反序（`.msupsub` 自上而下堆叠上下标，而源码书写顺序相反），其余交给 LCS 对齐安全失败——少放锚点，绝不放错锚点。

会话平面复用原生 `SessionInputShell`：本表面是唯一写者（每次编辑经 `setDraft` 推入），shell 侧变更（持久化种子、选中插入、发送清空）被收养回来，提交、排队、转向、通知、图片摄入与草稿持久化全部继承。撤销建立在源码之上——`(text, selection)` 快照加逐召回位置独立栈——因为装饰每击键重写 DOM，原生撤销追踪的是投影。

chain 条目拥有自己的完整 chrome（slot 系统按声明条目授权子渲染，原生 bar 的 chrome 槽无法从接管方重渲染）；`rich-composer` 设置命名空间的 `enabled` 开关可让出选举、恢复原生 bar。表面的内置手势由 `@zitro/dsh-oot-ui-stock-actions` 经本包提供的 `ctx.composer` 服务注册。

已知限制：所持文本读取层尚未归一化 Chromium 在纯文本可编辑区折叠岛周围报告的每个光标位置（岛邻读取可能与可视光标相差一个岛的跨度）；因此进入/离开边缘契约尚未在浏览器中钉住，点击扫描依赖字形框而非读取位置。

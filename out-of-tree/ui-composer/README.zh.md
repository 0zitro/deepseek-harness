# @zitro/dsh-oot-ui-composer

[English](README.md) | 中文

富文本 composer 编辑器：当选入 `conversation.composer.editor` 槽的 CodeMirror 6 表面，其文档就是完整的 Markdown 源码，外观是对它的实时装饰。浏览器从不直接编辑缓冲区——CodeMirror 把输入转换为对其自身文档的事务并渲染装饰——因此"原地装饰"可编辑区自带的那一整类缺陷（换行占位符、光标亲和映射、选择往返、收养回声）是结构性消失的，而不是被修补的。

装饰引擎移植自 katex-patcher 参考 composer：强调与代码来自增量 @lezer/markdown 解析加悬空起始符处理（单独的 `_` 立即斜体其尾部，`_**` 叠加，代码上下文抑制一切修饰符，因为由文法而非扫描决定什么是代码）、数学折叠为 KaTeX 排版并带字形到源码的偏移映射、围栏代码用客户端共享的 Shiki 单例着色。折叠是带 widget 的 replace 装饰；折叠跨度是原子区间，光标整跨过去，边缘处的删除整取对象。打开状态由每次重建时的光标推导——光标严格处于其内的对象按 Markdown 源码绘制，点击绘制在指针下方的字形即在该处打开，离开则重新折叠。

相对参考实现仍保留一处刻意偏离。参考实现逐一枚举其数学引擎的布局置换；本移植只写下唯一要紧的 KaTeX 反序（`.msupsub` 自上而下堆叠上下标，而源码书写顺序相反），其余交给 LCS 对齐安全失败——少放锚点，绝不放错锚点。参考实现的 `Range.toString()` 偏移约束在此不复存在：文档偏移就是 CodeMirror 自己的，绘制的字形以属性携带源码偏移供指针路径使用。

会话平面复用原生 `SessionInputShell`：本表面是唯一写者（每次文档变更经 `setDraft` 推入），shell 侧变更（持久化种子、选中插入、发送清空）以一次事务收养回来并以"文档对草稿"把关，提交、排队、转向、通知、图片摄入与草稿持久化全部继承。撤销是 CodeMirror 对源码的历史。

composer 经本包提供的 `ctx.composer` 服务注册自己的动作（`composer.*`、`commandPalette.*`）——组件拥有自己的手势。键绑定分发器在 window 捕获阶段、先于任何编辑器处理器认领已绑定的手势；未绑定的手势落回编辑器（纯 Enter 换行），加速和弦在空草稿时转向。`rich-composer` 设置命名空间的 `enabled` 开关让出选举：同一个 div 绑定原生 Lexical 编辑器为根，不改任何注册即恢复原生编辑行为。

已知限制：方向键整跨折叠对象而非打开它（点击可打开——Obsidian 式的方向键打开留作后续工作）；逐召回位置的撤销栈推迟到上游出现消息召回导航；GFM 表格与任务列表装饰为纯文本（`@lezer/gfm` 在本部署的 registry 镜像中不可达）。`@codemirror/*` 依赖钉在经过评审的 2026-08-31 发布列车上，其中 `@codemirror/view` 为精确版本（其下一版晚于仓库供应链的发布年龄窗口）。

# @deepseek-ai/dsh-client-ui-keybindings

[English](README.md) | 中文

快捷键编排器。客户端侧提供 `uiActions` 注册表，功能包在其中注册动作（action：id、标签、默认绑定，以及一个 `run` 处理器）；它在 `ui-keybindings` 设置命名空间中，为每个被调整过的默认绑定持久化一条局部覆盖项（override：`{ action, key, base, strokes?, when?, prio? }`），把生效的绑定渲染成表格，并把击键分发给匹配动作的处理器。注册方自行声明带 brand 的动作 id 与默认键；这些 brand 经 type-only import 抵达注册方，而跨插件的值导入正是客户端 bundle 所禁止的。

持久化模型命名的是 seat——`(action, key)` 这一对——以及对它的一份贡献。[seat 的 Agent Note](../../../.agents/notes/implemented/architecture/2026-08-16-keybinding-seats-and-contributions.md) 持有这套词汇，以及为什么一次存下来的调整所指向的是 seat，而不是当下坐在其中的那个手势。

## 已存储的覆盖项

渲染出来的列表只投影已存储的覆盖项，别的一概不投影：因此一次编辑是在被存下时出现，而不是在被做出时出现，被 Host 拒绝的写入也就无法在界面上留下一条重新加载后不复存在的绑定。每次写入都从已存储的列表推导出下一份列表；一旦没有已存储的列表——未读到、未提供服务或无法解码——就没有可推导的依据，于是该写入直接报错拒绝，而不是被允许替换掉它从未见过的那些覆盖项。

一次编辑只携带用户改动过的字段，并合并进已存储的覆盖项，而不是替换它。因此录制一个手势之后，`when` 子句仍然不出现在覆盖项中，绑定继续跟随其默认绑定的子句，日后对该默认绑定的改动依然能抵达合并后的绑定。用户主动清空的子句以空字符串存储，它不声明任何谓词、始终生效——这是覆盖项去掉默认绑定所带子句的唯一途径。

已存储的 base 会与外界持续对齐：只要注册方或持久化数据任一侧发生移动，这一轮对齐都会在一次写入之后即告收敛。默认绑定已不可用的覆盖项保留它先前留存的 base，而对齐过程从不触碰它已覆盖的那些字段。写回的只有用户自己的文档，因此对齐不会触碰插件贡献的任何内容。合并谁由排名决定——用户高于插件，插件高于随包提供的默认绑定，绝不会把三者揉在一起——而来源要么是随包提供的默认绑定，要么是用户，要么是以自身 id 具名的贡献插件；它是在读入时打上的，而不是自述的。

## 设置表格

这张表格用的是 [`dsh-client-ui-primitives`](../ui-primitives/README.md#tables) 里那张共享的表格：由它持有各列、列间的通道、移动通道的那些边界、行内单元格所站的那些组，以及住在单元格之间空间里的那些控件。本页面所陈述的，只是唯有它才知道的东西：每一列希望有多宽、一列不可被拖到多窄，以及按下这些控件各自意味着什么。

一列的下限就是它自己的表头——标签，加上它为排序标记保留的那份空间。各行对此没有发言权：行内字段会裁切、手势会滚动，因此若让一条长子句说了算，就会为本有去处的内容把整列撑开。

整个页面是覆盖所有行的一张网格——命令单元格纵跨它所拥有的那些行，这是任何逐行元素都做不到的——共五列：命令、快捷键、`when` 子句、优先级、来源。同一命令的各行彼此相邻，因为行按动作 id 的点号分段排序，命令因此只书写一次，在它的行段上居中。用户覆盖过的字段以斜体渲染，仍跟随默认绑定的字段则后退，这与已存储覆盖项所划出的区分是同一条。子句采用代码字体，因为它靠标点阅读；来源列则把它的短值居中。

覆盖项不会替换 seat 所提供的绑定；页面把两者都显示出来，随包提供的那条就显示在实际分发的那条之上，带删除线且不提供任何控件。只有实际分发的绑定才占据位置，因此被取代的行不声明优先级，也不消耗其冲突作用域中的任何空位；在按优先级排序的表格里，它排在每一条持有位置的行之后。不提供任何手势的 seat 只显示一行。

## 排序

点击列表头即按该列排序，各列按点击顺序累积，因此最先点击的那列始终最重要；一旦有多列参与排序，每个标记旁会出现次序编号。再次点击反转该列，双击将它移出排序——组成这次双击的两次单击会先各自切换该列，随后被这次移除丢弃，因此没有任何一次点击需要被压住等待，去确认它属于哪种手势。

列本身不携带比较逻辑：它声明自己持有哪种值，而这种值携带排序方式与首次点击的方向。正因如此，来源按优先次序而非字母排序，命令按点号分隔的各段排序，手势按它收尾的那个键排序，于是同一个键上的每条绑定都会聚到一起，无论它各自带着什么修饰键。排序是稳定的，因此某个排序无法区分的行保持它们进入时的次序，同一命令的各行只要在该排序下仍然相邻，就保持相邻。

表头是一个为一列所能携带的最宽标记——带着该排序会给最后一列的那个排名——留出空间的 run，因此列在加入或退出排序时不改变宽度，而它的标签为已画出的标记让路时，只让所需的那么多、绝不更多。

## 编辑字段

每个字段都在失焦时提交，因此半截输入的值绝不会被存储、绝不会被分发、也绝不会到达另一个客户端；未经编辑的草稿不提交任何内容，而在字段之下被改动的草稿会被替换。无法解析的子句会被标红且不予提交，因为存下它会解析为假，从而停用它所属的绑定。按键录制器是唯一的例外：手势没有有意义的中间形态，因此它在录制结束时提交。

优先级是一个数字字段，编辑期间允许为空：什么都不填是一次被放弃的编辑，而不是错误，因此该字段在失焦时不作任何抱怨地退回已存储的值，而一个无法在排序中占位的值会被标红并且不予提交。只有非负整数会被存储。

它的两个箭头由本页面绘制，而不是交给引擎，并且常驻显示而非悬停才出现，因为"被看见"正是它们的第二份职责：引擎自带的调节钮无论是否绘制都要占去自己的宽度，因此一份没有被标示出来的预留，看上去就像数值没有居中。这个字段是一个行（run），它在两端各预留一份箭头的形态、只占据尾端那一份，于是数值落在字段的中心上，而本页面不必为任何一侧陈述宽度。两个箭头都不是 Tab 停靠点，因为字段本身已经响应 Up 与 Down。一次按下只移动草稿，因此连按数次存下的是它最后停在的那个值，而不是沿途经过的那些；箭头以它所改变的数值命名，而不是以次序命名——0 是最高优先级，所以调大数值反而让绑定排得更靠后。

行上显示的优先级正是分发用来了结冲突的那一个——覆盖项声明的值，或者它在真正可能与之冲突的那些绑定中所处的位置。优先级只区分共享同一 `(stroke, source)` 的条目，此外别无所指，因此不与任何绑定竞争的绑定读作 0，只有真实的竞争才会往上计数。声明出来的优先级必须成立；播种填补它留下的空位，从低到高，因此未声明的绑定绝不会落到已被占用的位置上。声明优先级是把绑定放到那个位置，而不是提出一个可能被拒绝的主张：它取得该值，同一作用域内排在该位置及其之后的每条绑定都后退一位。命令已不再注册的绑定无法使用排序中的位置，于是它交出自己的优先级，而不是占住一个。

## 新增与删除绑定

新增绑定的入口位于某个命令的最后一条绑定与下一个命令的第一条绑定之间、任何盒子都不占据的那片空隙：一条 seam 悬挂在该命令所拥有的最后一条绑定之下，沿它任意处按下都会新增绑定，而不仅限于线中间的那个标记。该标记取用编辑器发送按钮与光标所用的强调色，因为它是表格中唯一会新增内容的东西。提交的只有控件，绝不是整条条带，因为新增目前还无法撤回，而条带所在之处正是一次瞄准盒子的点击可能落空的地方。

新增的绑定占据一个属于自己的 seat，其键取自它所依附的那个 seat 的家族——`send`，然后 `send#1`、`send#2`。它从那个 seat 的 base 分叉而来，而不是从零开始，因此它的子句跟随它所出自的那条绑定，并且仍可被清空或替换；它声明的手势不含任何击键：它从一开始就属于用户，并在用户录制之前保持惰性。

用户持有的绑定可以再被删除，入口位于该行自身边缘处的那道 gutter——它是通道中超出边界抓手的那部分宽度，因此一次瞄准列边界的按下，落不到表格中唯一一个具有破坏性的控件上。删除会保留 seat 所提供的绑定，因此随包提供的绑定回到页面上，而用户新增的绑定则彻底离开。它只出现在用户持有的绑定上：随包提供的默认绑定与插件的贡献都不由用户处置。

## 按键录制器

录制器捕获组合键：点击进入待录状态，随后每次非修饰键的 keydown 追加一次击键，按住的修饰键渲染为按下状态的按键块；录制器内部的对勾提交，Escape 或失焦取消，不带修饰键的 Backspace 删掉最后一次击键，锁定键抬起可复位卡住的修饰键，自动重复的 keydown 一律忽略。当指针位于一个有内容可解绑的录制器上时，同一位置会出现一个叉号，清除后存下的是不含任何击键的手势——空手势无法与任何输入匹配，于是该动作不再绑定到任何按键，而这条绑定仍归用户所有，可以再次录制覆盖。

两个控件都是绘制而非书写的，与排序标记共用同一块底板。宽度超出所在列的手势保持在一行内，靠滚动来阅读，因为换行会加深行高，而裁切则会把击键永久藏起来。击键在 window 上捕获，因此焦点无关紧要；修饰键状态从 `getModifierState()` 读取，并以布尔标志作为回退。

## 领域模型

`keybinding.ts` 由录制器、持久化 schema 与消费方共享：一条快捷键是一列有序的击键——一次击键是简单绑定，两次及以上是组合键（chord）——每次击键由一个非修饰键加一个可选的修饰键集合构成。匹配对修饰键严格相等，因此绑定的 `Ctrl+Enter` 在同时按住 `Alt` 时不会触发。单字母键一律以小写持久化，因此无论捕获时是否按住 Shift，同一个字母录制出的结果都相同。

可选的 `when` 子句（`when-clause.ts`）用 VSCode 语法（`&&`、`||`、`!`、`==`、`!=`、`=~` 与圆括号）把绑定谓词化到界面状态之上。它针对 `uiWhenContext` 求值，那是一张由焦点作用域栈（`<FocusScope>`／`data-focus-scope`）与显式状态键共同派生出的映射。Host 侧负责注册该设置命名空间。

## 已知限制与暂缓事项

- **子句可以指名哪些状态键，取决于各功能发布了什么，而且没有任何地方枚举它们**：编辑器声明了自己的焦点作用域，并发布 `commandMenuOpen` 与 `tokenLeading`，因此 `composerActive`、`commandMenuOpen`、`tokenLeading` 与 `controlActive` 可以求值；指名其他键的子句不会被拒绝；它永远不成立。设置字段无法提供一份它列不出来的清单。
- **无法通过拖动行来重排绑定**：在冲突作用域内放置一条绑定，目前只能靠声明优先级，而已声明的优先级无法再撤回：缺席意味着未声明，因此一个值可以被改动，却无法退回它原本所处的播种状态。
- **Linux 上的 Firefox 会过滤内容页面的修饰键事件**：组合 keydown 中不含 `Alt`，单独的修饰键 keydown 也从不派发给 `http` 页面（它们确实能到达特权的 `about:` 页面），因此 `Alt` 组合键与按键前的修饰键预览在那里不可用；Chromium 正常。录制器本就优先使用 `getModifierState()`；这些事件是缺席，而不仅仅是标志位有误。

# @deepseek-ai/dsh-client-ui-primitives

[English](README.md) | 中文

纯 React 原子组件（零 cordis）：StateDot、DisclosureRow、ic_ds_* 图标、Button/Pill/Menu/Modal/Input、Toast 短时横幅、OnboardingSurface 首次使用接管层（portal 到 body 的遮罩加不透明展示层，在且仅在自身生命周期内保持 `#root` 为 `inert`）、markdown 家族（MessageText/MarkdownText/JsonBlock）、只读 JsonTree 检查器、`useAnchoredMaxHeight` 钩子（把底部锚定的浮层高度收敛到锚点上方的视口空间，并在 resize、scroll 与调用方提供的依赖变化时重新测量）、TerminalBlock、DiffBlock、ReadBlock、SearchBlock、WebBlock，以及为时有时无的占位者留出空间的 FittedRun/ScrollingRun 布局。

## 悬浮卡片

`HoverCard` 通过指针离开宽限期，使采用 portal 渲染的预览在跨过与锚点之间的间隙时仍可触及。消费方还可传入 `copyText`：此时卡片为指针与键盘激活提供按钮语义，其无障碍名称会在 `copyLabel` 前缀后包含该值，通过包内剪贴板辅助函数原样写入该值，并且只有宿主接受写入后，才会临时将内容替换为 `copiedLabel`。与卡片相交的非折叠文本选区会阻止指针点击激活；成功反馈保持卡片原有高度，并随卡片关闭或在一秒后清除。`copyLabel` 和 `copiedLabel` 采用 label prop，是因为这个 zero-cordis 原子组件无法读取应用 locale；省略 `copyText` 时，卡片维持只读且可选择文本的行为。历史依据见[已归档的悬浮卡片复制 Agent Note](../../../.agents/notes/archived/feature/2026-07-31-hover-card-click-copy.md)。

## Toast

`Toast` 是顶部的短时横幅：滑入后满不透明度停留三秒，再用一秒淡出，随后调用 `onDone` 由持有方卸载。它渲染 `role="alert"`，带可选的前置图标插槽，文案是必填 prop（零 cordis，由持有方本地化）。它经 body portal 渲染且 `pointer-events: none`，距视口顶部 120px，水平中心跟随可选的 `anchor` 元素（窗口尺寸变化时重测）——composer 传入自己的卡片，横幅因此在聊天列而非整个窗口上居中——不传则回退到视口居中。重复展示同一条消息需要重新挂载，持有方用每次展示递增的序号作为 key，让相同文案重新走完停留与淡出，而不是静默复用已淡出的横幅。`prefers-reduced-motion: reduce` 下去掉滑入，只保留延迟淡出。它的层级高于 ui-attachment 的图片灯箱，预览打开时报出的失败仍然可读。

## Markdown 渲染

`MarkdownText` 通过 React 元素渲染来自不受信任 assistant 输出的 GFM 与 `$…$`、`$$…$$`、`\(…\)` 和 `\[…\]` TeX 公式，公式由 KaTeX 排版并禁用受信任命令；块级同一行 `$$…$$` 是显示公式并支持 `\tag{}`。一个小范围的 micromark 扩展允许由星号标记、以标点结尾的粗体在紧邻的 CJK 文本前闭合，以适应 CJK 文本通常省略 CommonMark 所要求空格的写法；单星号强调、紧邻非 CJK 文本的情况、转义、代码与数学公式仍沿用上游解析行为。它会省略原始 HTML，使相对链接及非 HTTP(S)/mailto 链接失效，以安全的外部链接属性打开 HTTP(S) 链接，并在不发送 referrer 的情况下渲染采用绝对 HTTP(S) URL 的图片；相对路径、绝对本地路径、`file:` URL 与不受支持的 scheme 会保留其 alt 文本。完整内容为绝对 HTTP(S) URL 的行内代码会保留代码样式，并获得同样安全的外部链接；命令、非完整 URL、其他 scheme 与围栏代码仍不会成为链接。可选的 `fileMentions` 解析器让持有该组件的视图为命名真实文件的行内代码添加可点击入口：token 保留代码样式，并获得一个连接到解析所得 opener 的按钮，按钮带有解析器提供的无障碍标签和以完整路径为值的 `title`。渲染器绝不猜测哪些内容像路径：未解析的 token 保持不可交互；文件提及仅应用于已定稿的渲染（流式缓存不得固化可能过期的 handler）；锚点内的 token 也保持不可交互，因为按钮不能嵌套其中。回复流式输出期间，`MarkdownText` 增量解析：除末尾两个块外全部冻结为缓存的 React 元素，每个分片只重新解析其后的源文本尾部，因此每分片的工作量跟随尾部而非整个回复（[机制与 DOM 一致性约定](../../../.agents/notes/implemented/architecture/2026-08-06-web-markdown-incremental-ast-renderer.md)）。`MessageText` 仍是用户创作内容使用的字面文本原语。`extractMarkdownPlainText` 会移除 Markdown 呈现标记以用于紧凑标签，同时将原始 HTML 保留为字面文本。元素间距、响应式图片、表格、链接与行内代码使用与 deepsuite `@deepseek/md` 相同的 `--dsw-alias-markdown-*` / `--dsw-font-markdown-*` token。围栏代码块通过 `CodeBlock` 渲染（语言横幅、复制控件，以及对已注册语法使用 shiki）。

## 终端输出

`TerminalBlock` 将一条 shell 命令渲染为终端表层：命令的每一行各占一个提示行（缩短后的 `cwd` 标签只出现在第一行，因为视图只知道一个工作目录，而一个 `cd` 就会让后面的行去到别处，标签之后是该行）、命令输出、非零退出码或终止信号对应的状态胶囊，以及写入原始 `output` prop 的复制控件。一枚运行状态 `StateDot` 为整次调用标记一次，位于第一行，以脱离文档流的方式落在卡片以自身左内边距预留的落区中，因此它位于卡片盒之内、提示文字之左。它用到 `StateDot` 的三种状态——`running` 期间为追逐动画，与渲染状态胶囊相同的退出状态为红色，其余为绿色——因此卡片直接陈述其命令是否仍在运行，而不是让人从有无输出中推断；由于 `StateDot` 是 `aria-hidden`，它携带一处视觉隐藏的文本标签。无论多少行都只有一枚状态点是有意为之：退出状态属于整次调用，因此每行一枚就会声称一个视图并不携带的逐行结果。命令文本使用 `white-space: pre`，因此重复空格、制表符与缩进续行都原样呈现，同时该行仍保持单行并以省略号截断。ANSI 转义序列通过运行时依赖 `anser` 解析为 React span；光标移动在剥除无显示意义控制符之前先重放进逐行的列缓冲，因为回车与退格**只移动**光标：单是 `100%` 加回车再加 `OK` 显示为 `OK0%`，而 spinner 随重绘写出的 `\x1b[K` 会擦掉尾巴，因此 `100%\r\x1b[KOK` 显示为 `OK`。行内擦除的三种参数形式都被遵循，光标按终端列推进（8 列制表位；emoji 与 CJK 占两列；组合标记不占列），SGR 状态按单元格归一化存储，与终端一致，并跨行延续、在行结束时的状态处收束；基础 16 色前景色映射到 `--dsw-*` token，而 256 色板与真彩色值按字面 rgb 透传。输出保持 `white-space: pre` 并支持横向滚动，因此按列对齐的输出保留其对齐而不会软换行；超过 `maxLines`（默认 16）时折叠为头部切片加尾部切片，由展开按钮控制。原理：[Web 终端卡片笔记](../../../.agents/notes/implemented/feature/2026-07-28-web-terminal-card.md)。

## Read 渲染

`ReadBlock` 将返回的文件窗口渲染为带行号、语法高亮的代码表层：一个粗体路径（或 presenter 提供的标题）横幅加复制控件，其下是内容行，行号槽里是文件自身的行号（窗口化的 read 保留文件本身的编号，因此偏移之后的 read 从大于 1 处起始）。`totalLines` 超过窗口行数时画出 `showing N of M` 提示；超过 `maxLines`（默认 16，与 TerminalBlock 相同的切分算法）时折叠为头部切片加尾部切片，由展开按钮控制。高亮走与 `CodeBlock` 相同的 shiki 路径。原理：[Web read 卡片笔记](../../../.agents/notes/implemented/feature/2026-07-30-web-read-card.md)。

## Diff 渲染

`DiffBlock` 将一次文件改动渲染为内联 diff 表层：每个文件一个粗体路径头、删除行（`- `，error token）在新增行（`+ `，success token）之上、同文件第二个 hunk 前一个 `⋯` gap，以及暗色 `└ +A -R · N file(s)` 页脚。各行使用 `white-space: pre` 并横向滚动，因此源码行保留其缩进而不软换行；超过 `maxLines`（默认 16，与 `TerminalBlock` 相同的切分算法）时折叠为头部切片加尾部切片，由展开按钮控制。新建（`oldText: null`）没有删除侧。复制控件写入带前缀的 diff 文本（路径头、`- `/`+ ` 行、gap），使多文件复制保持可归属，并浮在右上角而非占据自己的 banner 行。几何结构与 `CodeBlock`/`TerminalBlock` 一致。原理：[Web diff 卡片笔记](../../../.agents/notes/implemented/feature/2026-07-30-web-diff-card.md)。

## 搜索结果

`SearchBlock` 渲染一次已完成的搜索，并通过 `kind` 判别，由一个组件处理两种结果。`matches`（grep）将每个文件显示为粗体路径头及其 `lineNumber: line` 行，各文件组均可折叠；`paths`（glob）显示扁平的路径列表。两者都摊平成一个行列表，由高度上限对其做头尾切片（默认 16，与 `TerminalBlock` 相同的切分算法），且都不软换行：较长的匹配行或路径会横向滚动而非折行。当工具截断结果时，banner 摘要会包含截断前的总数（grep 为 `显示 X / 共 N 处匹配 · K 个文件`，glob 为 `显示 X / 共 N 个路径`），使卡片绝不把截断后的结果呈现为完整结果；无论是否触及上限或哪些组处于折叠状态，复制控件都会写入完整的结构化结果。几何结构与 `CodeBlock`/`TerminalBlock` 一致。原理：[Web 搜索卡片笔记](../../../.agents/notes/implemented/feature/2026-07-30-web-search-card.md)。

## Web 检索

`WebBlock` 渲染一次已完成的 web 检索，用一个组件绘制 `web` 渲染意图的两种 kind（由 `kind` 判别）。`search` 在有序引用列表上方显示可选的提供方回答（通过 `MarkdownText`）：每个 source 是一个安全外链，以其标题为标签，或以其主机名为标签，当 URL 无法解析或没有主机名（`file:`/`data:` URL）时回退到原始 URL，因此标签绝不为空；其下渲染 snippet 与发布日期。只有 http(s) URL 会成为锚点（设置 `target`/`rel`）——这是 `MarkdownText` 对不受信任链接所用 allowlist 的 http(s) 子集（该 allowlist 还允许 `mailto:`，此处排除）；任何其他 URL 渲染为纯文本。整份列表渲染在一个定高滚动容器里（`max-height: 320px`、`overflow-y: auto`），因此超出该高度的列表在原地纵向滚动，而不是把卡片撑高；`<li value>` 固定每个 source 的引用编号，从 1 起连续，而不依赖 `<ol>` 的隐式计数。当一次 search 合法地返回无 answer 且无 source 时，卡片显示一个明确的空状态提示，而不是空的 `<ol>`（chat 行不呈现原始 result content）。`fetch` 显示一个紧凑摘要：带链接的最终 URL 及其 HTTP 状态。两者都会标记一次被截断的检索。原理：[Web result 卡片笔记](../../../.agents/notes/implemented/feature/2026-07-30-web-result-card-frontend.md)与[来源滚动笔记](../../../.agents/notes/implemented/feature/2026-08-03-web-search-source-scroll.md)。

## 行（run）

行（run）是这样一段内容：它在某一端为时有时无的占位者预留空间——列标题上的排序标记、录制条上方的确认控件——无论占位者是否在场，这块空间都保持不变。这块空间以元素而非长度表述：调用方传入 `reserve`，即该端所能容纳的最宽形态，行把它隐藏渲染。这里没有任何测量，也没有任何规则携带数字，因此一个多出排名的标记无需被告知就能预留带排名标记所需的宽度。两种行在 RTL 下都自然镜像，不需要任何与方向相关的规则；`align` 提供的各交叉轴模式（`start`、`center`、`end`、`stretch`、`baseline`）下几何关系同样成立。

`FittedRun` 就地阅读其内容，由两个平面构成。尺寸平面决定这个行索要多少宽度：两个隐藏样本——内容的影子与 reserve——放在两条 `max-content` 轨道上，它们是流内仅有的东西，因此索要的宽度就是内容加上预留空间，而占位者无法改变它，因为它根本不在这个平面里。绘制平面则是一层覆盖层，按尺寸平面争得的宽度布局，承载读者看到的内容、预留空间与占位者；它可以按对齐要求随意摆放它们，因为它所做的一切都回不到尺寸里去。预留空间是否被占用，是这个行拥有的唯一状态：`occupant` 是站在里面的那个东西，而 `occupied` 表示它被行并不持有的某物占据——比如浮在行末端之上的控件，它无法嵌套进自己所浮盖的内容里。空着时，内容在整个行的范围内遵循所设的对齐。被占用时，绘制平面变为余量、内容、预留空间三条轨道，其尾部轨道以 reserve 兜底——于是内容落在 `min(富余, (预留 + 富余) / 2)` 处：只要还有可居中的余地就居中，偏离也只偏离占位者所需的那么多，而当富余达到预留空间的宽度时便完全不动。内容是最后才被牺牲的，排在余量之后、也排在预留空间分得的那份余量之后，因此这份预留永远不会裁剪它。

两个平面并非图省事的做法：只要内容在流内、且索要由内容与 reserve 共同提供，在下限处居中就是不可能的（[原因](../../../.agents/notes/implemented/architecture/2026-08-19-reserved-room-runs.md#why-two-planes-are-necessary)）。因此 fitted 行中内容的影子恰为 reserve 之镜像。它的代价是内容渲染两次，因此两次必须测得一样：应当是一段短语，而不是带 `id` 的子树，并且其换行不应取决于自己是哪一份副本。滚动行在这一项上不付任何代价，因为它索要的只有预留空间。两种绘制平面都用 grid 而非 flex，是为了 flex 没有的一条性质——`1fr` 轨道即 `minmax(auto, 1fr)`，轨道的最小尺寸与它在富余空间中的份额彼此独立；而 flex 项的基础尺寸会计入容器的 `min-content`，富余就被记到了下限上。

`ScrollingRun` 通过滚动来阅读其内容，它把同样的两件事分给两个平面，只是这两个平面是叠放而非分层的——因为滚动容器必须留在流内，才能给出行的高度、也才能让内容有自然的行。外层盒子只索要预留空间，别无其他，这对一个滚动容器而言才是诚实的索要：它对装不下的内容的全部回应就是滚动，因此再放一个内容的影子，只会把任何人曾放进去的最长内容的宽度硬塞给这一列。隐藏的 reserve 站在盒子那唯一的单元格里，索要正是由它而来，两种状态下皆然，因此不会有列因为占位者的到来而移动。旁边的滚动容器排布三条轨道，其内容轨道为 `max-content`——滚动行不会为了装下而收缩内容——并且只在预留空间被占用时才把它放进来。正是这一点让空着时两侧余量保持相等：没有东西浮在行末端之上，也就没有什么需要避让，内容只需遵循所设的对齐。一旦有了，尾部轨道便以预留空间兜底，内容偏离该对齐的量恰为占位者所需而不再多；而预留空间由于位于滚动内容之内，就成了把内容末端从它底下带出来的那段过滚区。若调用方的占位者时有时无，则需注意可滚动范围会随预留空间一同变化：预留空间到来时范围增长，离开时范围收缩，而收缩的范围会让引擎把任何越过新末端的偏移量夹紧——位置就在任何代码读到它之前被丢弃了。在意这一点的调用方应在预留空间尚在时把该位置记下来，并在它回来时还回去。滚动条被隐藏（`scrollbar-width: none` 与 WebKit 伪元素），`overscroll-behavior-inline: contain` 则防止横向手势上溯到祖先滚动容器。这里的 `justify` 只有 `start`、`center`、`end`：滚动内容没有可供拉伸的宽度。

## 表格策略

两个纯模块，不含 React、也不碰 DOM，装的是可排序可调宽表格中属于算术而非标记的那部分。`table-order` 表明列本身不携带比较逻辑：它通过一个 `Ordering` 声明自己持有哪种值，而这种值同时携带比较方式与首次点击所取的方向——名次向第一名递增，而时长通常希望最长的排在前面。`orderedBy` 把"列从哪里读取自己的值"与"这种值如何排序"绑在一起，并就地消掉值的类型，使得一张表的各列保持为一个同质列表，而不是任何数组都装不下的一族形状；消费方自己的列类型则在 `TableColumn<Row>` 之上扩展出绘制表头所需的一切，而那与排序无关。`toggleSort` 按点击顺序累积各列，因此第一个被点击的列始终最为显著，再点一次则就地反转方向；`dropSort` 移除某一列；`sortRows` 稳定地施加最终结果——正是这一点让调用方可以先把行分好组，并让这一分组在任何与之不冲突的排序下继续成立。指名了并不存在的列的排序不会失败，只是什么也不贡献，因为排序状态的寿命长于任何一套具体的列。

`table-resize` 只有一个函数。`resizeWidths` 移动两列之间的分隔条：一列所得即另一列所失，其余各列一概不动，且这一对的总和守恒，因此表格自身的宽度不会因一次拖动而改变。这里的宽度是像素而不是份额，因为只有在每一列都高于自己的下限时，份额才映射得到宽度——一旦把某列挤到它的下限上，它交不出来的那部分空间就会被重新分给这次拖动根本没碰过的列。两列都不会低于各自被给定的下限，而这些下限来自调用方：一列不可被拖到多窄，是对该列内容的一次测量，而其中哪些内容算数，是表格的拥有者所持有的策略，不是这套算术的性质。

## 表格几何

`Table` 只持有一个网格的各列与列间的通道，别无其他。那套坐标系——`tableColumnLine` 给出的列线、`tableLaneLine` 给出的通道线，以及由各列与任何已确定宽度算出的轨道模板——正是其他每一项特性借以组合的接缝，因此一张表格只为自己要的东西付费。既不要排序、也不要调宽、还不要跨行单元格的表格，就是 `<Table columns={…}>` 加上按它给出的线摆放的单元格：没有状态，没有处理器，没有边界。单元格用 `data-table-column` 说明自己属于哪一列，表头再加上 `data-table-heading`，调宽策略正是据此找到要测量的东西。

`TableGroup` 通过 subgrid 把连续若干行放在同样的轨道上，于是任何依附于该组的东西——挂在它下面的条带、横贯它的一条线——都有一个高度合适的东西可以依附：一个网格行的高度取决于其中最高的东西，而那很少是条带真正所属的那些单元格。它的 `from` 与 `to` 说明自己覆盖哪些列，因为跨越该组各行的那个单元格是站在组的旁边、而不是组的里面，并且它可以站在任何位置：表格的前缘、后缘，或者中间——而在中间时，它两侧的各列便是两个组，因为网格区域是矩形。

调宽是一个钩子加一个元素。`useTableResize` 持有各宽度——那是它自己的状态，不是任何人的副本——并交回驱动边界所需的处理器；要在会话之间保留布局的消费方，声明 `initialWidths` 并在一次手势结束时收到 `onWidthsCommit`，而不必持有拖动途经的每一个宽度。`TableSash` 是那个抓手：整条通道都能接住指针，因此边界沿其高度任意处都可被抓住；它是一个可获得焦点的 `separator`，通过 `aria-valuenow` 报告自己所处的位置，并可用 ArrowLeft/ArrowRight、Home 与 End 移动。它的 `span` 是一个 prop 而不是 `1 / -1`——后者是相对**显式**网格解析的，而行是隐式的表格并没有显式网格，因此那样写的分隔条只会站在第一行里：实测为 114px 高表格中的 22px。

下限有两个，回答的是不同的问题。列的轨道以它自己的 min-content 兜底，因此容不下各列的面板会滚动，而不是把它们裁掉。而**拖动**以 `floorOf` 所说的为下限，其默认值是该列各单元格在最窄时测得的宽度——即一列展示自己的内容——并且可以更为节省：行内单元格会裁切或滚动自身内容的表格，可以声明只有表头才把列撑开，于是一个长值无法为本有去处的内容去争夺宽度。`minContentWidth` 被导出以便书写这样的策略，并且它是测量而非假定，因为以数字写死的下限只是对某种字体的猜测。

## 表格的合并行

表格常常把一个值在它所属的那些行上只显示一次——命令显示在它的各条绑定之上，日期显示在它的各条条目之上。`runsBy` 找出这些"连续段"，而这个运算是相邻分组，不是关系型的那种：在**呈现**顺序中，键相等的极大连续片段——正因如此，把某个键的各行拆开的排序，也会把它的连续段拆开。于是同一个值在两处被读到两次，就是呈现如实地讲出了读者所选的那个顺序，而不是一个有待复原的缺陷。

`runId` 用键、以及"这是该键的第几段"来命名一个连续段，并把序号写在前面，好让一个可以自由拼写分隔符的键无法与邻居相撞。两半中任何一半单独都不够用，而且两种失败在顺序改变之前看起来都很对：只用键，会在排序把它拆开的那一刻相撞；而用连续段的第一行，则会因为行在编辑中来来去去而改变身份，并把读者正在进行的事一并带走。`tableRunRows` 负责摆放一个连续段，并把第一行的网格线作为参数，因为它之前有多少行表头是调用方的事实。

两个合并列默认彼此独立——两次互不知情的调用，其跨行单元格是位于不同轨道中的矩形。`runsWithin` 是另一种关系，即内层的值只在某一个外层值之内被读取；它是第二个函数而不是一种模式，因为表格想表达的是哪一种，得由表格自己说。

## 表格中的条带

表格会在单元格之间留出空间，而站在这片空间里、而不是站在某个单元格里的控件，就是一条**条带**。`TableSash` 已经是其中之一——列边界的可操作物——而 `TableSeam` 与 `TableGutter` 补完了这一族：seam 站在某个组下方、下一个组开始处的那道缝里，gutter 则站在其所在通道中超出抓手的那部分宽度里。两者都不占用自己的空间，因此无论表格是否提供它们，表格的高度都只等于它各行的高度；而按下它们**意味着**什么，从不抵达表格：两者都是带有 `label`、`onPress` 以及各自所绘内容的按钮。

让 gutter 变得安全的不是小心，而是通道的算术。一条通道是 `calc(通道 + gutter)`，分隔条保留通道那一份并把 gutter 那一份作为外边距让出，gutter 取走其余——于是抓手的像素与 gutter 的像素依构造即不相交；而在 gutter 的控件会销毁东西、抓手却是读者整天瞄准之物的场合，这一点尤为要紧。以 14px 通道加第一条通道上 14px 的 gutter 实测：该轨道解析为 28px，抓手占 289–303，gutter 占 303–317，重叠为零。

条带只在指针招呼过之后才绘制，并公布 `data-drawn`；它还公布指针沿其自身所处的位置——`--dsh-table-seam-y`、`--dsh-table-gutter-x`——并夹在自身范围之内。这个夹取就是"停住不动"规则的全部：已绘制的条带会以 `--dsh-table-seam-reach` 的距离在自身之外继续响应，因此位于触及范围内、却已在条带之外的指针会落到最近的一端，绘制随之停止跟随，而不是去追一个已经离开的东西。用命中测试实测：未绘制的 seam 只在自身范围内响应，已绘制的则在 6px 之外仍响应、而 14px 之外不再响应。所绘的标记是否跟随这个偏移量，是消费方的一条 `transform` 规则；条带决定的只是指针在哪里，从不决定这份反馈长什么样。

还有两个长度收尾。`--dsh-table-seam-inset` 是 seam 向两侧组内伸入多远，因此在什么都不声明时，seam 恰好就是行间隙那么厚——很薄，但有效。`--dsh-table-overhang` 是最后一行之下供 seam 站立的空间，因为表格会裁切自己的交叉轴，否则最后一条 seam 就会死在那道边上。

## 已知限制与暂缓事项

- **流式期间跨边界引用解析被推迟**：定义落在增量冻结边界另一侧的引用式链接或脚注，在回复流式输出期间渲染为字面文本；定稿时的全量解析会将其解析。内联链接以及在同一次解析内完成解析的引用不受影响。
- **字形级图标是重新绘制的近似版本**：鱼形标志（以及 ui-conversation 持有的闪光图标）来自字体字形，而本地设计数据无法导出其矢量几何；在获得精确导出路径前，使用手工重建版本代替。
- **Pill 与 Input 没有设计来源**：两个原子组件均自行定义；与其相似的侧边栏搜索字段和视图标签条由消费方组合，不是这些原子组件。
- **StateDot 没有 `Active` 变体**：支持的状态为 done、warning、ongoing 和 error。
- **面向用户的文案经 label props 本地化，默认值为原中文字面量**：这些原子组件是 zero-cordis 的，拿不到 `ctx.locale`，因此 `HoverCard`（`copyLabel`/`copiedLabel`）、`TerminalBlock`（`labels`）、`JsonTree`（`labels`）、`CodeBlock`（`copyLabel`/`copiedLabel`）、`MarkdownText`（`codeLabels`）、`JsonBlock`（`truncatedLabel`）、`ConnectionBanner`（`label`）和 `Modal`（`closeLabel`）都把文案作为可选 props 接收。已本地化的插件用自己的 `t` 席位传入字典驱动的 label；什么都不传的消费方得到的就是这些默认值。`WebBlock` 尚未跟进这一模式：它的来源列表截断提示与 fetch 截断提示、以及空搜索提示仍是内联中文，待同样的 label-prop 处理。
- **行信任其 `reserve` 就是最大形态，也信任其内容两份副本测得一致**：预留空间就是 reserve 实测的大小，因此比自己的 reserve 更大的占位者会溢出分给它的空间而不是把空间撑大；而允许内容换行的 `contentClassName` 可能让影子与可见副本在不同宽度处换行，从而使行的索要与其绘制脱节。两者都不做检测；由调用方给出最大形态并传入一段短语，或者接受由此产生的结果。
- **`TerminalBlock` 不是终端模拟器**：它渲染已结束或仍在运行的命令输出，而不是交互式会话：SGR 颜色与属性会被遵循，进度行所用的行内光标移动同样被遵循——回车、退格、行内擦除、制表位与字符宽度。绝对光标定位、清屏与备用屏幕序列会被剥离。基础 16 色中的洋红与青色没有对应 token，保持字面 rgb。

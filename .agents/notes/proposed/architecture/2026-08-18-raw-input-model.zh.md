# Agent Note: A catch-all binding for surfaces where raw input is the default

Status: proposed

[English](2026-08-18-raw-input-model.md) | 中文

## Problem

分发器假定命令是常规、原始击键是例外：匹配到绑定的手势触发一个动作（action）并认领该击键，其余一切则落到当前持有焦点的东西上。这个假定对编辑器、命令菜单和设置页都成立，而对把击键当作数据消费的界面则完全反过来——内嵌终端、游戏、拥有自己一套按键语言的模态编辑器。在那里，几乎每一个键都属于该界面，只有少数几个手势应当逃逸到应用层。

`when` 子句无法表达这种反转。子句把关的是上下文能够指名的分歧——某个作用域处于活动状态、某个菜单打开——而需要原始输入的界面问的并不是某个具名状态是否成立；它要的是接收输入事件本身，包括没有人绑定过的键，以及任何绑定都无法穷举的组合。给每个包里的每一条绑定都写上 `when: !terminalActive`，等于把这个例外逐条重述一遍，并把维护负担压在除了真正需要它的那个包之外的所有包身上，方向恰好是反的。

## Proposal

在绑定语法中加入一个通配模式：手势为 `*` 的绑定匹配任何抵达分发器的击键，并像其他绑定一样受自身 `when` 子句把关。需要原始输入的界面注册一个动作，其 `*` 绑定的作用域限定在自己的焦点作用域内，随后由既有的排名与优先级规则决定还有什么能压过它——排在通配之上的 Escape 绑定继续工作，而排在其下的一切再也看不到按键。

动作获得带类型的 `args`，使一个处理器可以服务多条绑定；参数值可以携带分发器在调用时替换的插值记号：`${inputEvent}` 表示匹配到的击键，`${activationGesture}` 表示该绑定所写的手势。未闭合的 `${` 按字面文本处理而不是报错，因此用户在设置字段里键入一个花括号，不会造出一条加载失败的绑定。

通配是已经落地的 `when` 把关式让渡（Space token 认领）的对偶：在那里，一条绑定主动让出它本可以认领的手势。让渡针对上下文能够指名的分歧；通配则针对只有处理器自己才能看见的分歧。

## Alternatives considered

- **用焦点作用域上的一个开关整体挂起分发**：否决——非此即彼的开关同时也会失去那些本应在该界面内继续触发的绑定（离开该界面的 Escape、应用自身的加速键），而要把它们重新放行，就得在开关内部重建一套优先级。
- **让该界面自行挂 window 监听器**：否决——先后次序重新变得随意，分发器的认领约定被绕开，而该界面的按键对设置页不可见，用户既看不到也无法重新绑定它们。
- **给现有的每一条绑定加 `when: !rawInput`**：否决——它把维护负担反转到所有并非提出诉求的包身上，而后来新增的包会悄无声息地漏掉这个例外。
- **在分发器旁另设一个原始输入服务**：否决——两个权威争夺同一条击键流，就需要一条规定谁先看到的规则，而那正是分发器已经持有的排序。

## Acceptance criteria

某个界面能够注册一条通配动作，并接收每一条抵达分发器的击键，同时具名绑定仍然压过它并正常触发。通配绑定像其他绑定一样出现在设置表格中，其手势可被如此读出。带 `args` 的动作接收替换后的值，`${inputEvent}` 携带匹配到的事件，而参数中含未闭合 `${` 的绑定会连同该文本原样加载。

## Risks

通配按构造认领击键，因此一条作用域写错的通配会让应用在其作用域内失声；在原始输入界面与一个看起来已死的键盘之间，唯一挡着的就是那条子句。插值还引入了第二处对绑定已存文本进行解释的地方，这是一处解析面，设置页必须如实呈现，而不是把它藏起来。

# Agent Note: Keybindings resolve as seats holding ranked contributions

Status: implemented

[English](2026-08-16-keybinding-seats-and-contributions.md) | 中文

## Problem

键盘行为过去由各自持有它的组件负责。`InputBar` 决定 Enter 的含义，每个浮层决定 Escape 的含义，命令菜单决定方向键的含义，因此没有哪个界面能够声明一条并非由它自己实现的绑定，任何绑定都无法重新绑定，而两个功能争夺同一个手势时，冲突只能以缺陷报告的形式被发现。在这样的安排之上做一个设置页是写不出来的：没有一份可渲染的绑定列表，没有可供存储调整的身份，也没有地方裁决两个主张者谁胜出。

真正困难的不是注册表，而是一次已存储的调整究竟指向什么。手势不是身份：把默认绑定改到 `Ctrl+Enter`，不能意味着这条已存储的记录从此指向别的、恰好持有 `Enter` 的绑定。`when` 子句同样不是身份：两条子句可能互相蕴含，而它们是否互相蕴含并非静态可判定，因此按子句文本作键会把一条绑定劈成永不再合的两条。

## Decision

动作（action）是功能注册的东西：一个 id、一个标签、一个 `run` 处理器，以及零或多条默认快捷键，每条都携带一个稳定的 `key`。这个 key 就是身份：`(action, key)` 这一对构成一个 **seat**，而 seat 的寿命长于坐在其中的手势，正是这一点让已存储的调整能在默认绑定的击键迁移之后依然成立。

对一个 seat 的**贡献**是一条 `KeybindingOverride`：`{ action, key, base, strokes?, when?, prio? }`。它只声明用户改动过的字段，因此它未声明的字段继续跟随默认绑定，日后对该默认绑定的改动依然能抵达合并后的绑定——若把合并后的值重述一遍，反而会把它冻住。`base` 快照的是该贡献所出发的那条默认绑定；只要任一侧发生移动，对齐过程就把当前默认绑定写回其中，比较是结构性的，因此对一份已对齐的列表再跑一次不会产生任何写入；默认绑定不可用时则保留原有 base，因为无法对齐并不等于无法合并。

贡献从不自述来源。设置文档按定义属于用户，插件的贡献则属于该插件，所以来源是在读入时打上的，一份声明无从主张自己并不具备的来源。合并谁由排名决定——用户高于插件，插件高于随包提供的默认绑定——且只有排名最高的那一条参与合并。一条不声明任何字段的贡献并不是空的：占住一个 seat 本身就是一种声明，因为这条绑定从此属于用户，高于它先前跟随的来源，并在用户的作用域而非那个来源的作用域中排序。

页面把 seat 所提供的绑定与接过它的贡献并排显示，前者惰性且带删除线，因为它正是贡献出发时的那一条，也是贡献消失后会回来的那一条。绑定还可以新增：新增的绑定占据一个属于自己的 seat，其键取自它所依附的那个 seat 的家族（`send`、`send#1`、`send#2`），这个后缀是任何注册方都写不出来的，因此新铸的键与随包提供的键共享同一命名空间也不会碰撞。

## Ordering and collisions

两条绑定在共享同一手势且都可能触发时发生冲突。跨来源的情形由来源排名了结；同一排名之内则由 `prio` 区分，其作用域恰好是 `(strokes, source)`——即真正可能相遇的那些条目。因此不与任何绑定竞争的绑定读作 0，只有真实的竞争才会往上计数。另一种做法是按整份列表播种，它并不成立：它会给彼此从不相遇的绑定编号，而由于每个播种值都互不相同，真实的冲突反而无从察觉。

声明优先级是把绑定放到那个位置，而不是提出一个可能被拒绝的主张：它取得该值，同一作用域内排在该位置及其之后的一切都后退一位。共享该作用域的只有用户已经贡献过的绑定，因此这种位移改写的是已经存在的贡献，绝不会凭空造出一条。以这种方式接管一条随包提供的默认绑定，会把它从随包提供的作用域挪进用户的作用域，而那里的位置早已被占，所以位置要放在这次编辑将会留下的世界里判定，而不是在它抵达时的世界里判定。

## Alternatives considered

- **按手势为已存储的调整作键**：否决——手势正是可变的那一部分。一次重新绑定会让记录改指向此刻持有旧击键的别的绑定，而随包提供的默认绑定一旦迁移，针对它做过的每一次调整都会被悄悄遗留。
- **把 `when` 子句纳入身份**：否决——子句相等并非语义相等。两条子句可能互相蕴含，而这一点无法静态判定，于是一条绑定裂成永不再合的两条记录，且两条都会分发。
- **把三种来源揉成一条合并后的绑定**：否决——插件的子句配上用户的击键，是一条谁也没写过的绑定。排名挑出一条贡献与默认绑定合并，这让每一条生效的绑定都可归属于单一作者。
- **让贡献自行声明来源**：否决——声明能主张的来源，插件就能伪造。在读入时打标记，使「属于用户」成为一个关于贡献抵达自哪份文档的事实。
- **拒绝一个已被占用的优先级**：否决——该字段是重排作用域的唯一途径，拒绝等于把唯一可用的手势变成一道谜题。改为放置并顺位后移，这正是用户键入它时的意思。
- **丢弃不声明任何字段的贡献**：在实现之后否决——它会把 seat 悄悄交还给随包提供的默认绑定，同时改变排名与优先级作用域，这是用户从未要求过的行为变化。
- **不在页面上显示被取代的随包绑定**：否决——它正是贡献出发时的那一条，也是贡献被删除后会回来的那一条；把它藏起来，会让解绑一条系统默认绑定读起来像是把它销毁了。

## Consequences

功能只需声明自己的默认绑定，不再实现按键处理；分发器仅在匹配成功或开启组合键时认领击键，因此未绑定的可打印键仍会抵达其下的输入框。每一条生效的绑定都可归属于单一作者与单一 seat，正是这一点让设置表格可渲染，也让已存储的调整能挺过默认绑定的迁移。

代价是维护者必须记住一套词汇：seat、贡献、base、来源排名，以及作用域为 `(strokes, source)` 而非动作的优先级。对齐过程同时也是一次写回——由于比较是结构性的，它在一次写入之后即告收敛，但这确实意味着一次注册变化可能产生一次并非由用户操作触发的设置写入。

`when` 子句只在运行时把关。它们从不进入身份，因此子句永不成立的绑定是惰性的而非缺席的；指名了没有任何功能发布的状态键的子句也不会被拒绝，它只是永远不成立。
